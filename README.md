# AI 个人生活助手

> **2026-11-04 前端与修复更新：** 新增目标管理，重做今日概览、模型配置和偏好设置。本轮测试结果、截图和待补功能见 [前端优化与问题排查](docs/前端优化与问题排查-2026-11-04.md)。下方历史状态请结合该记录与 HANDOFF 阅读；QQ 连接本轮暂未处理。

把「你的情况」变成「今天能执行的安排」，并通过微信提醒你。

> **当前状态：可运行、已测试、未上线。** 真实微信通道与真实模型都还没有接入（缺资质与 API Key），
> 详见文末「还没做的部分」。不要把它当成已经能用的产品。

---

## 它做什么

1. 你在网页上写下自己的情况、目标、固定安排（上课、睡觉）、偏好
2. AI 据此排出一份当天的计划，每条都带「为什么排在这」
3. 你确认后，计划生效；到点前通过微信提醒你
4. 你在微信里回「1 / 2 / 3」反馈完成度，系统据此调整后续安排

不是「待办清单 + 定时提醒」，而是「AI 生成规划 → 弱约束执行 → 反馈调整」。

## 快速开始（本地）

```bash
# 0) 一次性：把项目目录映射成 ASCII 盘符（本机路径含中文，PostgreSQL initdb 会崩）
subst Y: "<项目绝对路径>"

# 1) 装依赖
pnpm install --ignore-scripts   # --ignore-scripts 是本机沙箱限制，见 ADR-001

# 2) 起本地数据库（嵌入式 PostgreSQL，端口 55432）
pnpm db:up        # 前台常驻；另开一个终端做后面的步骤
# 或者用一次性方式：
pnpm db:migrate

# 3) 起网页
pnpm web:build
pnpm --filter @life/web start   # http://127.0.0.1:3100

# 4) 注册第一个账号（库里零用户时不需要邀请码，且自动成为管理员）
open http://127.0.0.1:3100/sign-up
```

没有模型 API Key 也能跑通：网页端会走**离线 mock**，只生成空计划并明确提示，不会编造安排。

## 怎么验证它是好的

七条命令，覆盖从单元到端到端的七个层次：

| 命令 | 覆盖 | 规模 |
| --- | --- | --- |
| `pnpm typecheck` | 三个 workspace 的类型检查 | packages + web + worker |
| `pnpm test` | 纯函数逻辑 | 124 个用例 |
| `pnpm test:int` | 真 PostgreSQL 集成 | 70 个用例 |
| `pnpm e2e` | 端到端走查（注册→提醒→反馈） | 17 项断言 |
| `pnpm db:verify` | 数据库级约束真的拦得住坏数据 | 4 条断言 |
| `pnpm db:rehearse` | 生产迁移路径（空库 deploy + 零漂移） | 5 项检查 |
| `pnpm config:check` | 部署配置的自洽性 | 13 项检查 |

```bash
pnpm typecheck && pnpm test && pnpm test:int && pnpm e2e
```

`test:int` / `db:*` / `e2e` 会自己起停数据库，不需要外部服务。

## 架构（一句话版）

```
apps/web      Next.js 控制台：录入、今日计划、设置、邀请码管理
apps/worker   任务队列（PostgreSQL SKIP LOCKED）、提醒生成与派发、入站回复
packages/
  domain      纯业务规则：计划校验、触发规则、状态机、提醒抑制
  planning    规划编排：上下文组装 + 双层校验（格式 + 业务）
  llm         多服务商适配（OpenAI 兼容 / Anthropic）+ 结构化输出修复
  channels    通道策略、推送窗口、消息渲染、回复解析
  db          Prisma schema、迁移、生成的 client
  shared      时区计算、错误模型
```

三条设计原则：

1. **模型不许算日期。** 今天的日期、可用时长、固定安排都由代码算好再注入 prompt。
2. **格式合法 ≠ 业务合法。** 输出先过 zod，再过 `validateProposedPlan`（重叠、越权、过期）。
3. **窗口关闭时不许假装发得出去。** 派发前就算出能不能推，不能推就降级并记录原因。

## 还没做的部分（诚实清单）

| 缺什么 | 影响 | 卡在哪 |
| --- | --- | --- |
| **真实微信通道** | 桥接适配器已就绪，但没有可连的桥接服务与真账号 | 需部署桥接服务 + 真微信号 |
| **真实模型验证** | 只用 mock 验证过管道，规划质量未知 | 需一个 API Key |
| **一次真实部署** | `docker compose up` 与 Dockerfile 未实测 | 需一台服务器 |
| **备份恢复演练** | 本机缺 `pg_dump`，无法执行 | 需有客户端的机器 |
| 显式同意留痕 / 内容过滤 / 举报入口 | 面向公众上线才必须 | 需产品决策 |

最后一条特别说明：项目所有者已决定采用「**用户自备微信号 + 协议登录**」路线
（见 [ADR-009](./docs/decisions/ADR-009-个人号协议登录.md)）。它确实没有推送窗口限制，
但**违反《微信个人账号使用规范》1.2.6**，账号可能被永久封禁。这不是合规方案，用前请知情。
