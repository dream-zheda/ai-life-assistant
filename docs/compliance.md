# 合规边界与数据实践

> **这不是法律意见。** 下面写的是「我们的实现是什么样」以及「上线前必须确认什么」。
> 真要做成对外服务，请找专业法务过一遍。

---

## 1. 先划清定位

决定合规成本的不是代码，是**服务范围**。

| 形态 | 大致触发什么 |
| --- | --- |
| 自己用 / 几个朋友用（邀请制、不公开注册） | 基本不触发生成式 AI 服务备案；但仍受个人信息保护的一般规则约束 |
| 面向不特定公众提供（公开注册） | 可能触发《生成式人工智能服务管理暂行办法》下的**备案/安全评估**，以及更严格的内容安全责任 |

**当前实现的第一版定位是「邀请制、少量用户」。** 这不是技术限制，是**主动选择的合规边界**。
一旦开放公开注册，这个边界就消失了。

因此代码里保留了这条硬约束：

- 注册必须有有效邀请码（`databaseHooks.user.create.before`，见 ADR-006）
- 只有引导期（库里零用户）才允许无邀请码注册

## 2. 个人信息保护（PIPL）

### 2.1 告知与同意

App 内提供 `/privacy` 页面，说明：收集什么、发给谁、存多久、怎么删。
注册页与设置页都有入口。

**这是"告知"，不是"同意"的完整实现。** 当前没有单独的勾选同意流程；
如果面向公众，需要补一个显式的同意步骤并留痕。

### 2.2 最小必要

| 类别 | 我们实际收集的 | 必要性 |
| --- | --- | --- |
| 账号 | 邮箱、密码哈希（Better Auth 处理，明文不落库） | 登录 |
| 档案 | 用户自由描述的生活状况、目标、偏好 | 规划生成 |
| 作息 | 固定安排（上课、睡觉等） | 时间冲突判断 |
| 进度 | 完成情况与比例 | 调整计划 |
| 通道 | 微信侧的对外标识、最后发消息时间 | 推送窗口判断 |

**没有收集**：真实姓名、身份证、地理位置、通讯录、设备指纹。

### 2.3 个人权利

| 权利 | 现状 |
| --- | --- |
| 查阅 | 网页端可看档案、目标、固定安排、计划、进度 |
| 更正 | 可编辑；没有历史版本对比界面 |
| 删除 | 删除用户会级联删除其计划、进度、提醒（`onDelete: Cascade`） |
| 导出 | ✅ `/api/export` 下载 JSON；**不含密码哈希、会话 token、OAuth 凭据** |

### 2.4 数据出境（重要）

模型调用会把**档案与目标文本**发给模型服务商。

- 用境内服务商（如 DeepSeek）→ 不出境
- 用境外服务商（如 OpenAI / Anthropic）→ **构成数据出境**，需要单独评估

代码里没有强制限制，靠部署时的配置决定。**上线前必须明确：用哪家、数据去哪。**

## 3. 生成式 AI 的特殊责任

### 3.1 AI 生成内容的标识

计划里的每一条行动都带 `reason`，且规划结果在界面上标注为 AI 生成、需要用户确认后才生效。
`Task.source` 字段也保留了 `ai` / `user` 的区分。

### 3.2 内容安全

当前**没有**输出内容过滤。模型可能生成不当内容，而我们会把它写进数据库并推送到微信。

上线前需要补：
- 输出侧的敏感内容检查
- 用户举报入口

### 3.3 不得提供专业建议

产品定位是「生活安排」，不是医疗、法律、金融建议。
这份边界应写进用户可见的说明里，也需要在 prompt 里明确约束。

## 4. 谁能看到数据

**必须对用户诚实：这不是端到端加密。**

| 角色 | 能看到什么 |
| --- | --- |
| 用户自己 | 自己的全部数据 |
| 服务器/数据库管理员 | **理论上能看到所有人的明文数据**（数据库未做字段级加密） |
| 模型服务商 | 本次请求里携带的档案与目标文本 |
| 其他用户 | 看不到（接口层强制按 `userId` 过滤 + 数据库复合外键约束） |

管理后台目前没有"浏览他人私人档案"的入口，但这只是界面约束，不是密码学保证。

---

## 5. 保留与删除

| 项 | 现状 |
| --- | --- |
| 业务数据 | 不设自动过期，随账号存续 |
| 备份 | 每日备份，保留 14 天（见 runbook） |
| 删除账号 | 级联删除业务数据；**备份里的副本会保留到备份过期** |
| 日志 | 不以明文记录完整对话内容（约定见规划书 §13），但未做代码级强制 |

「删除即彻底」目前**不成立**，对用户说明时必须讲清楚。

## 7. 面向公众上线前的检查清单

- [ ] 确认服务主体资质（营业执照），评估是否需要生成式 AI 服务备案
- [ ] 明确模型服务商所在地，判断是否构成数据出境
- [ ] 补显式同意流程并留痕
- [ ] 补输出内容安全过滤与举报入口
- [ ] 在隐私说明里写清"备份保留 14 天"
- [ ] 确认日志不落明文对话
- [ ] 找法务过一遍本文件与 `/privacy` 文案
