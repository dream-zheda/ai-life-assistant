# 前端优化与问题排查 · 2026-11-04

本轮范围：优化前端、修复已确认的问题、整理后续功能。按用户要求暂不处理 QQ 连接、NapCat 登录及外部账号绑定。

## 页面与功能变化

- 桌面侧栏与手机横向导航，明确当前页面；统一配色、卡片、按钮、表单、焦点状态和移动布局。
- 今日页：安排数量、完成数、计划分钟数、当前/下一行动、时间线、准备情况、提醒与快捷入口。
- 生效计划与待采纳草稿分别展示；不会因为生成草稿而看不到仍在执行的计划。
- 新增 `/goals`：新增和编辑目标、说明、优先级、期望日期，以及暂停、恢复、达成、结束状态。只将 ACTIVE 目标用于后续生成；不擅自修改当前生效计划。
- 模型页：同步切换服务商预设、显示/隐藏新输入的密钥、测试与保存的等待状态。测试成功仍需保存。
- 设置页：提醒表单、暂停开关、数据导出、模型入口；删除账号收进展开区。
- 首次注册正确显示引导期；登录、注册、退出的网络异常可恢复重试。
- 增加可重试的页面错误边界和主要表单提交中的状态。浏览器走查发现全局 loading 边界配合当前框架的重验证跳转会出现空白，因此未保留该全局边界；保留提交等待提示。

## 已修复问题

| 问题 | 修复 |
| --- | --- |
| 最新草稿遮住生效版本 | `loadTodayPlans` 分别查询生效版和更新的草稿 |
| 网页能把已完成行动改回没做 | 复用领域状态机，事务内锁定与去重，禁止终态回退 |
| 可以对草稿或旧版本提交进度 | 服务端要求本人且计划为 ACTIVE |
| 邀请码创建成功却报错 | 将 Next.js `redirect` 移出 try/catch |
| 错误或测试消息含 `%` 导致异常 | 删除对已解码 searchParams 的重复解码 |
| 模型切换仍保留旧地址、旧密钥 | 前端同步更新预设；后端要求切换服务商/地址时重新提供 Key |
| URL 中带 localhost 即允许明文 HTTP | 解析 URL 并精确比较 hostname；拒绝地址内凭据、查询参数和 fragment |
| 测试连接绕过完整配置校验 | 保存和测试均调用 validateModelInput |
| 固定安排无效，却已经保存档案或目标 | 全部输入预先校验，所有写入放进一个事务 |
| 个人描述清空后无法保存 | 明确提交空值可清空档案内容 |
| 计划版本与条目分别保存 | 同一事务创建，串行分配版本号 |
| 并发采纳冲突、旧草稿覆盖新生效版本 | 用户行锁内重新读取、检查版本、更新状态 |
| 替换计划后旧提醒仍排队 | 同一采纳事务中取消旧版本待发送提醒 |
| 没配置模型也创建空计划 | 返回可操作错误，不写入无意义的 mock 草稿 |
| 生成失败只显示“原因见下方”但无原因 | 显示业务失败原因，异常时保留当前计划并提示检查连接 |
| 设置允许提前 120 分钟，worker 只扫描 60 分钟 | 扩展扫描范围与设置上限一致 |
| 提前完成后仍生成/派发开始提醒 | 生成和派发前均排除已完成/取消条目，网页完成反馈取消排队提醒 |
| 未到发送时间就被页面说成通道故障 | 首页只对 FAILED/FALLBACK_REQUIRED 给出对应说明 |
| SENT 被描述成已送达 | 使用“通道已接受”，不推断用户已收到或阅读 |

## 本轮未覆盖及后续优先级

### 下一轮应优先补齐

1. **网页对话与局部重排**：目前可生成日计划，但缺少完整的“今天累了/临时有事”的聊天与调整闭环。重排必须保留已经完成的进度与锁定行动，不能只生成一份全新计划。
2. **计划历史与稳定任务身份**：目前保留版本数据但缺少历史页面；不同版本的行动身份和进度尚未统一。新增历史查看、版本差异与可控撤销。
3. **资料版本校验**：模型生成期间档案、目标、约束可能变化。当前已解决计划落库原子性和版本号并发，但尚未实现完整快照冲突检查，采纳前也应重验最新约束。
4. **后台生成任务**：模型生成仍在 server action 中执行。补持久化任务、超时/取消、刷新后恢复、额度统计，适应长耗时调用。

### 多用户或公网部署前复核

- 提醒派发的并发领取、租约与幂等：现有通知派发仍有多 worker 同时读取并发送的风险，本轮没有重构派发队列。
- 网络发送结果未知与外部重试、断线恢复、旧提醒补偿，需要真实通道单独验收。
- 模型地址的完整 SSRF 防护、DNS/重定向检查、密钥解密失败提示；本轮仅修复 URL 校验和跨地址复用密钥问题。
- 首位管理员注册的并发处理、邀请码消耗与注册失败的事务关系、管理员有邀请记录时的删除行为，需要专门回归。
- 认证生产环境密钥、Secure Cookie 设置和 HTTPS 部署需检查。
- 目标/档案/约束更改会影响后续计划，但尚不会自动重排已生效计划；页面已明确告知。

### 后续体验能力

- 一周目标建议、日终复盘与长期趋势。
- 可查看、确认、纠正和删除的长期记忆。
- 一次性约定的录入、完整历史与搜索。
- Anthropic 等原生协议的用户配置入口：底层有适配器，但当前页面仍是 OpenAI 兼容接入。
- 时区编辑、表单失败保留输入、危险操作二次确认与更完善的可访问性。

## QQ 单机器人多用户

按用户提出的产品方向，已把 QQ 从“每个用户手填号码”调整为“管理员维护一个机器人账号，多个用户各自验证绑定”。改动与管理员启动步骤见 [QQ机器人接入](QQ机器人接入.md)。绑定码一次性、10 分钟过期，数据库仅存哈希；所有提醒路由、入站反馈按已验证 QQ 的唯一绑定查找。好友申请走队列并可配置自动通过，默认关闭。

已用隔离 PostgreSQL 验证真实事务、绑定码重放与过期、跨用户抢占、无效机器人事件、好友申请队列幂等、自动同意重试及已验证提醒路由。状态轮询端点只返回当前会话用户的绑定号码，并用集成测试验证两用户隔离。兼容本机 NapCat `detail_type` 私聊事件。NapCat 已在本机启动，`get_login_info` 返回配置的账号 `3463802115`，状态接口报告在线；还没有用户绑定、好友申请或真实提醒的端到端验收。Docker 运行方式仍未实测。

## 接手与运行说明

- 使用项目原有 pnpm 9.15.4 与 lockfile；运行 `install --ignore-scripts --frozen-lockfile`、`db:generate` 后再启动。
- 本轮未新增运行依赖。QQ 绑定功能新增 `qq_link_codes` schema 与 migration；部署时需按文档运行 `prisma migrate deploy`，该迁移只建表、不清数据。
- 本轮单独安装的格式化工具和浏览器检查工具不属于项目运行依赖。
- Windows 中文路径的 embedded-postgres 初始化仍有环境限制：本轮使用独立 V 盘映射，并通过 ASCII 路径直接调用 initdb 与 share 目录完成初始化。不要误用原项目数据库运行破坏性验证脚本。
- 新页面需重新 `web:build`；生产服务要重启，避免继续运行旧构建。dev 与 build 不要同时使用同一 `.next`。
- `scripts/frontend-browser-review.mjs` 是可复现的浏览器验收脚本。必须显式设置 `FRONTEND_REVIEW_CONFIRM=isolated`，并使用名称含 review/test 的独立数据库。Playwright 位置可通过 `PLAYWRIGHT_MODULE_PATH` 指定；浏览器路径用 `BROWSER_EXECUTABLE_PATH`，也可使用 Playwright 已安装的 Chromium。
- 浏览器脚本会创建和清理 `review-ui-` 前缀的演示账号，不可在正式数据库运行。启动本地端口 3110；不调用真实模型，不触发 QQ/微信连接。

文档里的测试数以本次执行结果为准，旧 AGENTS/HANDOFF 中的历史进度与数字不代表当前验收结果。
