# ADR-003：重复约束与跨零点时段怎么建模

- 状态：已采纳
- 日期：2026-11-03
- 相关：`packages/domain/src/planning/fixed-slots.ts`、`packages/planning/src/context.ts`

## 背景

固定约束（上课、上班、睡觉）有两种时间形态，而其中一种会静默算错。

数据结构：

```ts
type FixedSlot =
  | { kind: "weekly"; weekday: 1..7; startTime: "HH:mm"; endTime: "HH:mm"; timeZone }
  | { kind: "one_off"; localDate: "YYYY-MM-DD"; startTime; endTime; timeZone };
```

`fixedSlotIntervalOnDay(slot, day)` 只回答一个问题：**这条约束在 `day` 这一天占用了哪一段绝对时间**。

## 问题：跨零点的约束只属于"开始那天"

以「每天 23:00–07:00 睡觉」为例。

只声明一条 `weekly`（weekday = 2，周二）时，2026-11-03（周二）当天的占用是：

```
周二这条：23:00 Nov3 → 07:00 Nov4，裁剪到 Nov3 当天 → 只算 23:00–24:00 = 60 分钟
```

而 `00:00–07:00` 这 420 分钟属于**周一那条**约束的尾巴。如果只声明一条，`computeBusyMinutes` 会少算 420 分钟——于是 AI 会被允许把行动排到凌晨 2 点。

这个错误**不会报错、不会告警**，只会让可用时长算多，然后计划排得过于乐观。属于典型的静默错误。

## 决策

**保留「一行一条规则」的存储形态，不在数据库层做展开。** 由写入侧（设置服务）负责把「每天」这类表达展开为 7 条 `weekly`。

理由：

1. 展开后每条约束仍然可单独编辑、暂停、设有效期（例如"考试周取消健身"），语义不变。
2. 避免在 schema 里引入 `DAILY` 这种"既是规则又是展开"的混合体——一旦有了它，`one_off` 与 `weekly` 的边界会变模糊。
3. 计算逻辑保持纯粹：一个函数只判断"这条规则在这天占多少"，不需要知道"每天"的概念。

**代价（必须记住）：**

- 设置界面如果只给一条「每天」开关，服务层必须写出 7 行；漏掉任一天，那天凌晨就会算错。
- 已经写了单元测试固定这个行为（`computeBusyMinutes` 单条跨零点约束 = 60 分钟），并用注释写明原因，防止后来者"顺手优化"成 480。

## 未采纳的方案

| 方案 | 未采纳原因 |
| --- | --- |
| 增加 `kind: "daily"` | 会让"规则"与"展开结果"两种语义混在一张表里，后面做例外（法定假日、考试周）时很难表达 |
| 存储时直接把约束展开成具体日期的区间 | 无法表达"无限重复"，且每次改作息要重写大量行 |
| 在 `computeBusyMinutes` 里特殊处理跨零点（自动把尾巴补到前一天） | 会让"某天占用"不再是局部计算，`day` 与相邻日耦合，跨时区时更难推理 |

## 修正（2026-11-03）：只展开 7 条**还不够**

上面的方案写完后，集成测试直接把它否掉了。

`fixedSlotIntervalOnDay(slot, day)` 回答的是「**这条规则**在 day 是否生效」。
周一的规则在周二返回 `null`——于是周二凌晨 00:00–07:00 仍然不会被计入占用。
实测：7 条展开后，周二当天仍然只算出 60 分钟，而不是 480 分钟。

**根因不只是"展开得不够"，还有"取值的时候只看当天"。**

补充的修正：

1. 新增 `fixedSlotIntervalsOnDay(slot, day)`，同时返回**当天生效的**和**前一天生效但溢出到当天的**两段区间。
2. `computeBusyMinutes` 与 `validateProposedPlan` 都改用这个函数。
3. 调用方仍然要自己把区间裁剪到目标日期，否则会把前一天的完整区间也算进来。

于是正确的组合是：

| 措施 | 解决的问题 |
| --- | --- |
| 展开成 7 条 | 让"每天"的每个夜晚都有一条规则声明 |
| 同时看前一天 | 让前一条规则的尾巴进入当天的占用 |

两条缺一不可。只做第一条会退化成"每晚只算 60 分钟"，只做第二条则因为没有周一的规则而拿不到尾巴。

回归测试：

- `apps/web/tests/constraints.int.test.ts`：7 条展开后当天占用 = 480 分钟；对照组单条 = 60 分钟
- `packages/domain/tests/planning.test.ts`：凌晨 2 点会与「周一的 23:00–07:00」冲突；不跨零点的前一天约束不会误伤今天
