# ADR-009：个人微信号协议登录（用户自备账号）

- 状态：已采纳（产品决策，由项目所有者拍板）
- 日期：2026-11-03
- 相关：`packages/channels/src/wechat-bridge.ts`、`packages/channels/src/policies.ts`

## 决策

允许用户使用**自己注册的微信号**，通过扫码把账号登录到我们部署的桥接服务上，
AI 以该账号的普通好友身份发送提醒。

选它的原因只有一个：**它是唯一能同时满足「随时推送」和「用户用微信收消息」的路径。**

| 通道 | 能随时推 | 用户用微信收 | 合规 |
| --- | --- | --- | --- |
| 个人号协议登录 | ✅ | ✅ | ❌ 违反微信规范 |
| 认证服务号 | ⚠️ 类目与频次受限 | ✅ | ✅ |
| 企业微信应用 | ✅ | ❌ 需装企业微信（除非「微信插件」可用，未验证） | ✅ |
| 短信 / 邮件 | ✅ | ❌ 不在微信里 | ✅ |

## 必须承认的代价

### 1. 违反微信平台规则

《[微信个人账号使用规范](https://webgrab.wechat.com/cgi-bin/readtemplate?&t=page/agreement/personal_account&lang=zh_TW#1)》（2024-11-22 版）明确禁止：

| 条款 | 内容 |
| --- | --- |
| 1.2.6 | 通过**非腾讯开发、授权的第三方软件、插件、外挂、系统，登录或使用**腾讯软件及服务 |
| 2.3 | 不得利用多个账号主体或**控制多个微信账号**从事违规行为，亦不得采取技术手段**恶意避开或违反平台规则** |
| 12.5 | 微信账号的**买卖或租用**、商业化使用属违规内容 |

处罚梯度是「限制功能 → 短期封禁 → **永久封锁、回收账号**」，且腾讯有权公告处理结果。

**我们不做任何"这不违规"的辩护。它就是违规的。**

### 2. 账号随时会死，而且是无声地死

这是产品层面最严重的后果：**用户不会立刻知道自己的提醒已经失效了。**

所以本实现强制要求：

- `ChannelBinding.sessionState` 建模登录态（`PENDING_SCAN` / `ACTIVE` / `EXPIRED` / `DISCONNECTED` / `BANNED`）
- 非 `ACTIVE` 时派发必须走降级路径，并在界面上明确告知「微信提醒已中断」
- 降级通道（网页/邮件/短信）不是可选功能，是这个通道的**前置条件**

### 3. 用户把账号交给了我们

即使用户自己授权，我们事实上在**控制一个属于他的实名账号**，能看到这个账号的全部消息。
这一点必须写进隐私说明与用户协议，不能靠"用户自己选的"糊过去。

## 本实现的收敛措施

| 措施 | 原因 |
| --- | --- |
| **绝不存储密码**，只走扫码 | 密码一旦落库，泄露后果不可逆；扫码是唯一不需要我们保管凭据的方式 |
| 只存 `bridgeSessionId` 引用 | 会话由桥接服务持有，我们随时可以断开 |
| 本地令牌桶限速（默认 6 条/分钟） | 突发高频是最典型的封号画像，提前压平优于等服务端 429 |
| 401/403 不重试 | 凭据失效时重试只会加重风控 |
| 网络异常记 `unknown` 而非 `failed` | 我们不知道消息有没有出去，当失败重试会重复打扰用户 |
| 入站强制 HMAC 校验 | 桥接服务暴露在公网时，没有签名等于任何人都能伪造用户消息 |

## 明确不做的事

- ❌ 批量注册账号、养号、代实名
- ❌ 绕过微信风控（改设备指纹、模拟正常用户行为以规避检测）
- ❌ 群发、加好友、拉群等营销动作
- ❌ 把账号转租给第三方

这些不只是"风险更高"，它们会把民事违约变成别的性质的问题。

## 未验证的部分

| 项 | 状态 |
| --- | --- |
| 桥接服务能否稳定登录 | **未验证**（需要一个真账号 + 一台桥接服务） |
| 封号概率与存活时长 | **未知**，无法在开发机验证 |
| 微信是否检测到协议登录 | 几乎必然会，只是时间问题 |
| 「微信插件」等合规替代是否可用 | **未验证**，若可用应优先考虑 |

## 后续需要产品决策的事

1. 用户协议里如何写封号风险与责任划分（用户选的是"用户自担"，但需要在协议里可执行）
2. 账号被封后是否退费、如何告知
3. 是否提供"仅网页提醒"的降级套餐
